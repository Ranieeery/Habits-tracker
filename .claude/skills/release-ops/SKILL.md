# CI/CD and operations (Phase 8, 2026-10-11)

Owner decisions, moved from the root `CLAUDE.md`. The runbook is `README.md` (pt-BR at the owner's request, an exception to "docs in English"). Never run remote commands (deploy, migrations, secrets, backups, EAS) without the owner.

- **Topology** kept as is (two Workers, same origin, `/api` gateway): it already gives same-origin cookies, a private API and tests independent of the web build. A single Worker would save one deploy step but couple the API build to the web.
- **GitHub Actions**: `checks.yml` (reusable: frozen install, format, lint, typecheck, test, `migrations:check`, web build, `wrangler deploy --dry-run` of both Workers; no secrets), `ci.yml` (pull requests, weekly and manual, not branch pushes, so each PR runs once; plus `pnpm audit --prod` with step-level `continue-on-error`: advisories become a warning annotation and the check stays green), `deploy.yml` (push to `main`: checks, then one job in the `production` environment **with required approval**: D1 export to R2, `migrations apply --remote`, API, web, smoke test of `/api/v1/health`, `/api/v1/docs` = 404 and the CSP header, then `eas update` on channel `production` when `apps/mobile`, a package it uses or the lockfile changed; concurrency without cancellation), `backup.yml` (weekly export to R2 after a `/health` check, environment `backup` without reviewers and with its own D1 + R2 token). Actions pinned by SHA: checkout 7.0.1, setup-node 7.1.0 (Dependabot bumps the pins weekly), cache 6.1.0 (`.turbo`), pnpm/action-setup 6.1.0 (pnpm 12 from `packageManager`, store cache). Wrangler runs from the lockfile (`pnpm exec wrangler`), not `cloudflare/wrangler-action@v4`: one less third-party action, same version as local. eas-cli 24.8.0 via `pnpm dlx`.
- **Dependabot** only for `github-actions`: it supports pnpm up to v10 and the repo uses pnpm 12. npm updates are manual.
- **Cloudflare tokens**: deploy = Workers Scripts, D1 and Workers R2 Storage Edit plus Account Settings Read; backup = D1 and R2 Edit plus Account Settings Read.
- **`database_id`** stays in `wrangler.jsonc`: it is an identifier, not a secret, and the database already exists.
- **Backups** in a private R2 bucket `habits-backups` (90-day lifecycle; `pre-deploy/` and `weekly/`), never workflow artifacts (public repo). Time Travel (7 days on Free) for recent mistakes. A `wrangler d1 export` dump cannot be applied as is to an empty database (tables in name order with their rows, so `account` rows come before the `user` table): `db:restore:prepare` (`scripts/sql-dump.ts`) puts tables, rows, indexes and the sync triggers last, verified locally with identical counts, `server_seq` sum and triggers. Production restores go to a new database and the binding is switched.
- **Migrations guard**: `scripts/migration-guard.ts` blocks `DROP`, `ALTER TABLE … RENAME` and `DELETE FROM` unless the file has `-- migration-guard: destructive-ok <reason>`; `0002_user_fk.sql` (table rebuild) is grandfathered because applied migrations are never edited.
- **Web headers** (`public/_headers`): CSP with `script-src 'self'` (the build has no inline script) and `style-src 'self' 'unsafe-inline'` (sonner and Radix inject `<style>`); nosniff, `strict-origin-when-cross-origin`, `X-Frame-Options: DENY` plus `frame-ancestors 'none'`, a deny-all Permissions-Policy, `no-cache` on the shell, service worker and manifest, and immutable `/assets/*`.
- **Mobile**: expo-updates 57.0.25, `runtimeVersion` policy `fingerprint` (an automatic OTA can never reach a binary with different native code; `appVersion` would rely on remembering a version bump). Since 2.1.0, `fingerprint.config.js` skips the app config versions (`version`, `versionCode`), so version bumps that only change JS still reach installed builds; adding the skip changed the hash once (2.1.0 needed a new build), `updates.checkAutomatically: ON_LOAD`. eas.json: `appVersionSource: remote`; development / preview / production profiles, all internal APKs, channels `preview` and `production`, EAS environments of the same names (`EXPO_PUBLIC_API_URL` is a plain-text EAS variable; `eas update` requires `--environment` since SDK 55), and `autoIncrement` on production. The keystore and the FCM V1 key live in EAS; the owner keeps a keystore copy outside the repo (losing it means uninstalling, which wipes unsynced changes). Builds and OTA updates must compute the fingerprint on Linux: a build started from Windows fails on EAS with "Runtime version mismatch", because pnpm truncates `node_modules/.pnpm` folder names differently there (shorter max length) and the paths are part of the hash. `mobile-build.yml` (manual, environment `production`) starts EAS builds from Ubuntu with `--no-wait`; `deploy.yml` publishes updates from Ubuntu; `apps/mobile/.fingerprintignore` excludes the generated `android/` and `ios/`.
- **Alerts** without paying: GitHub emails on failed deploy/backup runs (the backup doubles as a weekly `/health` monitor) and EAS build emails. No real-time alerting for 5xx, CPU or cron failures: Workers Logs, kept 3 days.
