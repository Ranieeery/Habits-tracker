# apps/web

Vite + React 19 PWA (secondary client). See the root `CLAUDE.md` for architecture, date rules and the Phase 4 decisions.

## Setup

- `cp .env.example .env`: `VITE_API_URL=/api` (the browser's API base, same origin) and `API_PROXY_TARGET` (dev/preview only: where Vite proxies `/api/*`, with the prefix stripped). Never hardcode an API URL.
- Run the API (`pnpm --filter api dev`) and `pnpm --filter web dev`. The service worker is off in dev: use `pnpm --filter web build && pnpm --filter web preview` to test the PWA.
- Production builds read `.env.production` (committed, no secrets: `VITE_API_URL=/api`, `VITE_VAPID_PUBLIC_KEY`); the build itself needs no `API_PROXY_TARGET`.
- `VITE_VAPID_PUBLIC_KEY`: the API's `VAPID_PUBLIC_KEY` (public). Empty means notifications show as unavailable. Push only works with the service worker, so test it with `build` + `preview` (Chrome treats `localhost` as secure).

## Layout

- `src/main.tsx`: builds the real services (API client, auth, clock, device time zone) and the router; renders `<App>` plus `UpdatePrompt`. `src/App.tsx`: providers shared with the tests.
- `src/router.tsx`: code-based route tree. `/login` is public; the pathless `app` route guards the rest (`beforeLoad` checks the session, `loader` caches the settings that "today" needs). `createAppRouter(services, { history })` also creates the QueryClient, whose 401 handler sends the user to `/login?redirect=`.
- `src/lib/`:
  - `services.ts`: `Services` (`api`, `auth`, `push`, `now`, `deviceTimeZone`, `newId`) through `ServicesContext`. `systemClock` is the only place that reads `Date.now()`; `systemNewId` makes UUID v7 ids (Web Crypto) for records the app creates.
  - `push.ts`: `PushService` (support state incl. iOS-not-installed, permission asked only from the reminders switch, `PushManager` subscription, subscription id in `localStorage`). `push-payload.ts`: what the service worker shows and where a click goes (shared with tests).
  - `auth.ts`: `AuthService` over `better-auth/client` (`/v1/auth` under the API base), errors mapped to `AuthError` reasons.
  - `queries.ts`: query keys, `queryOptions` and mutation calls for every resource. Components never call the API client directly.
  - `use-today.ts`: `useToday()` = `todayIn(settings.timezone, now())`, refreshed on focus, `visibilitychange` and every minute. Always the saved time zone, never the device's.
  - `format.ts`: dayjs `pt-br` formatting only (date math stays in `@habits/core`). `errors.ts`: pt-BR messages for API errors. `redirect.ts`: same-app paths only after login.
- `src/features/<screen>/`: `auth` (login), `heatmap` (the home screen, 2.4.0 identity: `heatmap-page.tsx` with "Ano anterior"/"Próximo ano" arrows within core's `heatmapYearRange`, one summary query per year, plus the current year's (and, when core's `overviewNeedsPreviousYear` says so, the previous year's) for `overview-strip.tsx` (core's `overviewStats`); `heatmap-grid.tsx`: ARIA grid built row-major from `buildYearGrid` + `monthLabels`, roving tab stop (`nextCellIndex` in `heatmap-utils.ts`), one `heatmap-lens.tsx` ring that glides to the hovered/focused cell (the cells' own focus outline is off; native `pointerleave` on the grid, since React's synthetic one can fire between two cells) with the shared `heatmap-tooltip.tsx` traveling with it, entrance sweep and today's pulse (`pulse.ts`), mounted with `key={year}`, a past year scrolls to its end; `today-panel.tsx`: today's items (`useDayItems` + `DayItemsList`, overdue habits first); `heatmap-states.tsx`: skeleton, empty and error states), `day` (day view; `day-pages.tsx`: `DayPage` with "Voltar ao histórico" and arrows to the neighbor days, and `use-day-shortcuts.ts` (Esc back to `/`, ←/→ to the neighbor day; nothing with a dialog or popover open or while typing); `day-habit-item.tsx` is the habit row shared with the heatmap's "Hoje" panel (2.8.0: optional overdue badge, with an explicit `aria-label` "Nome, atrasado desde …", since a hidden text inside the label is read with a space before the comma); `use-day-items.ts` + `day-items-list.tsx` are the reusable rows of a day (on today, "today's items" with the overdue habits from the API's `overdue`, progress from core's `dayItems`), used by `DayView` and the panel; tests in `overdue.test.tsx`; optimistic toggle with "Desfazer" in `use-toggle-completion.ts`, past-day unlock in `past-day-bar.tsx`; on today only, "Novo hábito" in the header or as the empty state's action: `new-habit-dialog.tsx` reuses `HabitForm` with every day selected, one id per opening, and `use-create-habit-today.ts` adds the habit to today's list at once when it counts today, or toasts core's `newHabitNotice` ("Aparece em: seg, qua") when it does not; a failure keeps the dialog open with what was typed), `habits` (2.12.0: `habit-page.tsx` at `/habits/$habitId` shows the whole description with "Editar" (`edit-habit-dialog.tsx`), `description-popover.tsx` is the note icon and quick look of `DayHabitItem`, `components/description-text.tsx` renders core's blocks and `components/ui/textarea.tsx` is the form's field; cards in `habit-card.tsx`: the week strip with the habit's days lit and today marked, or the kind's icon and `formatSchedule`, plus "Hoje"/"Próxima"; the active list is reorderable with `use-sortable-list.ts` (handle: pointer drag and keyboard) and up/down buttons (from `md`; a "Mais ações" menu on phones), saved by `use-reorder-habit.ts` through core's `moveHabit`; list with `formatSchedule`, a collapsed "Passados" block for past single dates and "Incompatível" for unknown schedules; dialog with one id per opening; `HabitForm`: "Repetição" chips, weekday and month-day pickers, `date-field.tsx` (dates as `dd/mm/aaaa` with a month calendar in a Popover; not `<input type="date">`, which follows the browser's language), day/month `<select>`s, "Começa em", a preview, the inline confirmation before changing a repetition, all from core's `habit-draft.ts`), `day/upcoming-section.tsx` ("Próximos" on today, from the habits query and core's `upcoming`: one card per occurrence with `DateChip` and `ScheduleStrip` from `habits/schedule-summary.tsx`), `settings` (time zone with "Hoje é …" and a one-click "Usar o do dispositivo"; switch rows in `setting-row.tsx`; "Sair" behind an alertdialog; notifications in `reminders-section.tsx`/`use-reminders.ts`: morning digest switch at the fixed 09:00 (turning it on also registers this browser), reminder time as hour and minute `<select>`s in 15-minute steps, "Mostrar nomes nas notificações", optimistic with rollback, test push; enabling the digest or the reminder shows its own error unless the save hook already showed one (2.8.1, `reported` in `use-reminders.ts`); sign-out that unregisters this browser first, `TimezoneBanner`). The app layout re-registers this browser on load when permission was already granted.
- Navigation: the active link (`data-status=active`, `aria-current="page"` from the router) is an accent-tinted pill with an inner ring on top, and a pill behind the icon plus a top bar on the bottom bar (never color alone).
- Reading screens (today, day, habits, settings) are centered `mx-auto max-w-2xl` columns; the heatmap uses the full `max-w-6xl` frame.
- `src/components/`: app layout and nav (`wordmark.tsx`, `backdrop.tsx`, also used by the login), loading/empty/error states, route states, `update-prompt.tsx`. `src/components/ui/`: `select.tsx` (a native select styled like `Input`, no Radix), `popover.tsx` (shadcn/ui popover) and shadcn/ui components (added with `pnpm dlx shadcn@latest add <name>` using `components.json`, then restyled with token classes and `@/lib/utils.ts` imports; the CLI may add stray dependencies such as `cn` or `next-themes`: remove them).
- `src/sw/`: the service worker (vite-plugin-pwa `injectManifest`). `sw.ts` only imports modules: `lifecycle.ts` (SKIP_WAITING, `clientsClaim`), `app-shell.ts` (precache + navigation fallback, `/api` excluded), `push.ts` (`push` shows the validated payload, `notificationclick` focuses/navigates an open window or opens `/today`). No runtime caching: API responses are authenticated and never cached.

## Rules

- Only token classes (`bg-night-surface`, `text-night-muted`, `bg-night-heat-3`, `text-night-danger`…), never raw colors. Heatmap level classes are literal strings in `features/heatmap/heatmap-utils.ts`.
- Visual identity (2.4.0, `DESIGN.md`): the whole web uses only the `night` set (`bg-night-surface`, `text-night-muted`, `bg-night-heat-3`, `font-display`…); `src/tokens-guard.test.ts` fails on any class of the older set (kept in the theme for the mobile). Shared primitives carry the look (`Button` `default` = night accent, `success` only for "done"), so screens rarely need colors of their own. Focus color and thin night scrollbars live in `styles.css` (page via `html`, inner scrollers with `data-scrollbar="night"`); the background goes on `body`, never `html`, or the fixed glow layer (`components/backdrop.tsx`) is painted over. Dates and titles capitalize only the first letter (`first-letter:uppercase`, never `capitalize`). Motion: transform/opacity only, `motion-safe:` classes plus `usePrefersReducedMotion()` (`lib/use-reduced-motion.ts`) for anything started from JS; no animation library.
- Interactive elements keep the 44px minimum (`min-h-touch`, `size-touch`); the global `:focus-visible` outline lives in `styles.css`.
- Day view editing follows core's `getDayEditState` (2.3.0): today is editable; a past day up to `BACKFILL_DAYS` (30) back is read-only until "Editar este dia" is confirmed (`features/day/past-day-bar.tsx`: alert dialog with Cancelar focused, then the `warning` notice "Editando dia passado" with "Concluir edição"); older days say why; future days and heatmap placeholders stay read-only. The unlock is `DayView` state only (`DayPage` keys it by date): never stored, never in the URL. Every saved change shows a sonner toast with "Desfazer" for 6 s (`use-toggle-completion.ts`: one at a time, dismissed when the day locks or the view unmounts). No recurrence or date logic in the app: schedules, form validation, previews, "Próximos" and relative dates come from `@habits/core`.
- UI text in pt-BR. Imports inside `src` use the `@/` alias with explicit extensions.

## Tooling

- TypeScript projects: `tsconfig.json` (app, DOM, excludes `src/sw`), `tsconfig.sw.json` (WebWorker), `tsconfig.node.json` (`vite.config.ts`, `vitest.config.ts`), `tsconfig.worker.json` (`worker/`, Workers types). `typecheck` runs all four; `build` runs `typecheck` then `vite build`.
- `vite.config.ts` reads the theme color from `@habits/design-tokens` for the manifest and the `theme-color` meta, and exports `baseConfig` reused by `vitest.config.ts`.
- Tests: two Vitest projects in `vitest.config.ts`: `app` (Testing Library in jsdom) and `worker` (node, `worker/**/*.test.ts`). For app tests, `src/test/setup.ts` stubs `scrollTo`, `ResizeObserver`, `matchMedia` and pointer capture (sonner's toast actions) and clears sonner toasts. `src/test/harness.tsx`: `renderApp(path, options)` renders the real router with a fake API (`"METHOD /v1/path"` handlers), fake auth, a fixed clock (`NOW` = 2026-10-09 in São Paulo; `findBy`/`waitFor` wait up to 3 s, set in `setup.ts`), a device time zone, `fakePush()` (unsupported unless overridden) and predictable ids (`ids` option, then a counter); `renderInRouter(ui)` renders one component inside a minimal router.
- ESLint extends the root config plus `react-hooks` and `react-refresh` (`eslint.config.js`): keep non-component exports out of `.tsx` component files.

## Deploy (public Worker `habits`)

- `wrangler.jsonc`: Workers Static Assets from `./dist` with the SPA fallback; `run_worker_first: ["/api", "/api/*"]`, so only API calls run `worker/index.ts`. `worker/gateway.ts` (`toApiRequest`) strips `/api` and forwards the request as is through the `API` service binding to `habits-api`. After editing `wrangler.jsonc`, run `pnpm --filter web cf-typegen` (`worker/worker-configuration.d.ts`, generated, not linted or formatted).
- `public/_headers` (static assets only; API responses get their headers from the API): CSP (`script-src 'self'`, since the build has no inline script; `style-src` allows inline because sonner and Radix inject `<style>`; everything same-origin; `frame-ancestors 'none'`), nosniff, `Referrer-Policy`, `X-Frame-Options: DENY`, a deny-all `Permissions-Policy`; `no-cache` on `/`, `/index.html`, `/sw.js` and the manifest so a deploy is seen at once; `/assets/*` immutable for a year. Adding an inline script or a third-party origin means updating the CSP. `worker/headers.test.ts` guards these rules (typechecked by `tsconfig.node.json`, since it reads the file with `node:fs`).
- `pnpm --filter web run deploy` = build + `wrangler deploy`. Deploy the API first when both change (the binding target must exist, and the new web may call new API routes). In production the `deploy` workflow does this after the API and smoke-tests the CSP header; see the runbook in `README.md`.

## Decisions

Moved from the root `CLAUDE.md` (owner decisions; they override anything that seems to contradict them).

- **Web client** (Phase 4): code-based TanStack Router routes (no `routeTree.gen.ts` codegen, so `tsc` never depends on a generated file); everything but `/login` sits under a pathless `app` route whose `beforeLoad` redirects to `/login?redirect=`, and any 401 from the API does the same. Sign-in only: the API exposes no "owner exists" check, so there is no signup screen. Session via `better-auth/client` with the cookie on the web origin. The web calls the API at `VITE_API_URL` (`/api`, same origin): the Vite dev and preview servers proxy `/api/*` to `API_PROXY_TARGET`, stripping `/api`; in production the public Worker strips it the same way (see "Production topology"). "Today" is `todayIn(settings.timezone, now())`, re-evaluated on focus, `visibilitychange` and every minute; a different device time zone shows a banner (update or keep, never silent). shadcn/ui components are copied and restyled with token classes only (no shadcn color variables). `danger` (red-400, red-950 surface) was added to the tokens for error UI. PWA: vite-plugin-pwa `injectManifest` with `src/sw/sw.ts` (Phase 6 adds a `push.ts` module to it); precaches only the app shell (Latin font subsets), no runtime caching, `/api/*` excluded from the navigation fallback. Update strategy `prompt`: a new worker waits until the user taps "Atualizar" (SKIP_WAITING + reload); the page checks for updates hourly and on `visibilitychange`. In production `index.html` and `sw.js` are always revalidated (Workers Static Assets default). Versions: Vite 8.3, @vitejs/plugin-react 6.1, TanStack Router 1.170, TanStack Query 5.104, vite-plugin-pwa 2.0 / Workbox 7.4, shadcn CLI 4.21 (not a dependency) with radix-ui 1.7, sonner 2.0, dayjs 1.11, jsdom 30, Testing Library 16.
- **Visual redesign, stage 1** (2.4.0): see "Visual redesign" in the root `CLAUDE.md`. Web specifics: the display font is declared once in `styles.css` from `@fontsource-variable/bricolage-grotesque/files/…-latin-wght-normal.woff2` (the package has no per-subset CSS; importing `wght.css` would add every subset); `public/_headers` and the CSP did not change. Tests: `matchMedia` is stubbed per test to cover reduced motion; WAAPI (`element.animate`) is absent in jsdom, so `pulse` is a no-op there; the app QueryClient retries 5xx twice, so error-state tests use a 4xx.
